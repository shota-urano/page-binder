# デザイン原則（正本）

## トーン

**誠実・実用・静か。** 装飾より情報。プライバシー重視の完全オフラインツールとしての信頼感を、
ロゴ由来のフレンドリーな丸み（ブルー×ミント）で和らげる。マーケティング的な演出・
グラデーション多用・イラスト過多はしない。

## 情報密度

中密度。書籍一覧・ページ一覧（最大500ページ）を素早くスキャンできることを優先。
1画面1目的。書籍詳細画面だけはハブとして導線を多く持つ（統計+6導線）。

## 対象デバイス

Android スマートフォン縦持ちが基準（minSdk 29）。タブレット最適化はMVP対象外。
フローティングUIは他アプリの上に重なるため、背景を選ばない暗色半透明+白文字で固定。

## アクセシビリティ・安全方針（requirements §16.4 由来）

- 状態を**色だけで区別しない**。文字+アイコンを必ず併記（撮影中/停止中/連続撮影中、OCR状態）
- 破壊操作（削除・完全削除）は対象の件数・容量を見せてから確認する
- 権限要求の前に、必要理由と許可後の動作を画面内で説明する
- タップ領域は最小48dp
- 本文コントラスト: `--color-text` on `--color-background` で WCAG AA を満たす

## モック画像の読み方（実装者向け・厳守）

`docs/design/mockups/` のモック画像は**端末フレーム込みで描かれた参照資料**であり、次はモックの飾りであって**実装対象外**:

- 端末の外枠・ベゼル・側面ボタン
- ステータスバー（時刻「14:32」・電池・電波アイコン）と下部ナビゲーションバー — **OSが描画する。アプリ内に自前で描かない**
- モック内のサンプルデータ（書籍名「実践Kotlinプログラミング」・著者「山田太郎」等）— 例示であり、ハードコードしない

実装するのはアプリのコンテンツ領域（アプリバーから下、ナビゲーションバーより上）だけ。数値は画像からの目測でなく [`01-tokens.md`](./01-tokens.md) に従う。

## 文言の方針

- 日本語・です/ます調・簡潔。専門用語（OCR・SAF等）は初出時に短い説明を添える
- 法務系文言（初回同意4点・書き出し時確認）は specs の文言を正とし、デザイン側で言い換えない
