# ML Kit 日本語 OCR（bundled）品質評価スパイク

- 対象 issue: `pagebinder-c2s.1`
- 実施日: 2026-08-27
- 実行環境: Android Emulator `Google sdk_gphone64_arm64`、API 35（AVD `pixel-api35` / `emulator-5554`）
- OCR エンジン: ML Kit Text Recognition v2 Japanese bundled `com.google.mlkit:text-recognition-japanese:16.0.1`
- テスト: `MlKitJapaneseOcrSpikeTest`

## 総合判定

**横書き本文は採用基準を満たすが、raw ML Kit 出力の縦書き読み順には重大な問題がある。**

合成した日本語横書き本文の文字正解率は **100.00%** で、仕様の95%以上という目標を達成した。一方、縦書きは認識文字数が正解37文字に対して36文字だったにもかかわらず、文字列順序を含む正解率が **45.95%** に留まった。ML Kit の出力文字列をそのまま本文として採用できず、後続実装で文字座標に基づく縦書き読み順補正と、実書影での再評価が必須である。

縦書き・ルビ・複雑な段組みの製品目標値は、各1件の合成画像だけでは確定しない。実書影を含む固定コーパスを用意した後に確定する。

## 資料区分ごとの測定結果

| 資料区分 | 正解文字数 | 認識文字数 | 編集距離 | 文字正解率 | 判定 |
|---|---:|---:|---:|---:|---|
| 日本語横書き | 73 | 73 | 0 | **100.00%** | **PASS**（95%目標達成） |
| 日本語縦書き | 37 | 36 | 20 | **45.95%** | **重大な問題あり**（raw 出力の読み順不正確） |
| ルビ | 44 | 44 | 0 | **100.00%** | 合成画像では認識可 |
| 二段組み | 63 | 63 | 0 | **100.00%** | 合成画像では認識可 |
| 図表を含むページ | 31 | 30 | 1 | **96.77%** | 合成画像では概ね認識可 |
| 白黒反転・セピア背景 | 61 | 61 | 0 | **100.00%** | 2画像の合算。合成画像では認識可 |
| 小さい文字 | 91 | 91 | 0 | **100.00%** | 28 px 合成文字では認識可 |

文字正解率は `(1 - Levenshtein編集距離 / 正解文字数) × 100` とした。比較前に正解・認識結果の Unicode 空白文字と改行を除去し、Unicode コードポイント単位で挿入・削除・置換を数えた。句読点と英数字は文字として含め、表記変換や読み順の入れ替えは許容していない。

白黒反転・セピア背景は仕様上の1区分として、白黒反転1画像とセピア背景1画像の正解文字数・編集距離を合算した。他の区分は各1画像を測定した。

## 生成・測定条件

- 画像は instrumented test 内の Android `Canvas` で 1200×1800 px、ARGB_8888 の Bitmap として生成した。
- 描画フォントはアプリ同梱の Noto Sans JP 2.004-H2 variable TTF `app/src/main/assets/fonts/NotoSansJP-wght.ttf` を使用した。
- 横書きは日本語4行と英数字、縦書きは右列から左列へ3列、各列を上から下へ描画した。
- ルビは26 pxのひらがなを64 pxの本文上部へ配置した。
- 二段組みは左右2列、図表は本文・棒グラフ・日本語の月ラベルを配置した。
- 白黒反転は暗色背景に白文字、セピアは淡褐色背景に濃褐色文字を配置した。
- 小さい文字は28 pxで3行描画した。横書き本文は54 px、縦書きは52 pxを使用した。
- `InputImage.fromBitmap(bitmap, 0)` を bundled Japanese recognizer へ渡し、回転補正や読み順補正を加えない raw ML Kit 出力を正解テキストと比較した。
- 全区分を同一 APK・同一テスト実行内で測定した。画像や OCR 全文はログへ出力していない。
- ML Kit の推移依存が宣言する `INTERNET` / `ACCESS_NETWORK_STATE` 権限は、アプリ Manifest の merger rule で除去した。マージ済み debug Manifest に両権限が存在しないことを確認した。

## 判明した制約

1. **縦書きの raw 出力順は製品要件を満たさない。** 文字の検出自体は37文字中36文字相当まで行われたが、期待する「右列から左列、列内は上から下」の文字列順と大きく異なり、編集距離20、正解率45.95%となった。`docs/specs/09-ocr.md` §3.4 の座標ベース読み順補正を実装し、補正後に同じ固定資料で再測定する必要がある。
2. 全資料は実書影ではなく、Canvas 合成画像による近似である。圧縮ノイズ、モアレ、傾き、影、端末ごとの画面密度、書体差、実際のルビ組版、複雑な図表・段組みを代表しない。このため、縦書き等の製品目標値を本測定だけで確定しない。
3. ルビ100%は、本文とルビの間隔が十分ある単純な合成配置での結果である。実書籍の密接したルビや異体字で同等の精度を保証しない。
4. 二段組み100%は単純な左右2列での結果である。見出しが列をまたぐページ、三段以上、図の回り込みは未評価である。
5. 小さい文字100%は1200×1800 px画像上の28 px文字での結果であり、縮小処理後の実効文字高がこれを下回る場合は別途評価が必要である。

## 再現コマンド

```bash
./gradlew --console=plain :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=com.pagebinder.app.spike.ocr.MlKitJapaneseOcrSpikeTest
```

テストはアプリの external files 領域へ `c2s-1-mlkit-ocr-metrics.txt` を生成する。測定ファイルは再現確認用の一時成果物であり、リポジトリには含めない。
